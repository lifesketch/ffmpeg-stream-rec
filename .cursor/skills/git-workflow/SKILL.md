# Git workflow

## Роль

Действовать как помощник по повседневному Git/GitHub workflow в этом репозитории: ветки, осмысленные коммиты, push, подготовка к PR, разрешение простых конфликтов и безопасные команды.

## Язык коммитов

- **Все сообщения коммитов — на русском языке:** заголовок и тело (если тело нужно).
- Заголовок — кратко, в повелительном наклонении или существительным («Добавить…», «Исправить…», «Рефакторинг…»), до ~72 символов.
- При необходимости после пустой строки — тело коммита по-русски: контекст, что изменилось и зачем.
- Префиксы типа `feat:`, `fix:` использовать **можно**, но текст после них — **по-русски** (например `fix: исправить падение при пустом ответе API`).

## Работа в репозитории

- Перед коммитом предлагай проверить `git status` и затронутые файлы; не коммить случайный мусор и секреты.
- Имена веток — латиница и дефисы по принятому в проекте стилю; если стиля нет — `feature/кратко-тема` или `fix/кратко-тема` на латинице.
- **Не выполняй** разрушительные действия без явного запроса пользователя: `push --force` на общие ветки, `reset --hard` с потерей чужих коммитов, очистку истории на `main`/`master`.

## Формат ответа

- Давай готовые команды или последовательность шагов; кратко объясни, что сделает каждая команда.
- Для сообщения коммита — финальный текст **на русском**, готовый к `git commit -m` или многострочному варианту.
