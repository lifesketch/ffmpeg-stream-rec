# Руководство пользователя: запись HLS в MP4

Веб‑интерфейс для записи потоков **HLS** (плейлист `.m3u8`) в файлы **MP4** на сервере с помощью FFmpeg. Роль в системе одна — **оператор**.

Техническое задание и терминология: [flask_ffmpeg_recorder_spec.md](business-requirements/flask_ffmpeg_recorder_spec.md).

---

## 1. С чего начать

1. Запустите приложение так, как описано в [README.md](../README.md) (локально `python -m recorder` или Docker).
2. Откройте в браузере адрес, который выводит сервер (часто `http://127.0.0.1:5000` или другой порт; в Docker по умолчанию порт хоста **8080** — см. `HOST_PORT` в `.env`).
3. Убедитесь, что у вас есть **право записывать** выбранный поток (лицензия, договор, внутренние правила).

---

## 2. Главная страница: блоки

### Верх страницы

Краткая справка по **режимам хранения** (подробно ниже) и баннер **«Идёт запись»**, если есть активные сессии. Размер текущего файла на диске обновляется примерно раз в 1,5 секунды.

### Новая запись

| Поле | Описание |
|------|----------|
| **URL потока** | Ссылка на HLS, обычно заканчивается на `.m3u8`. Разрешены только `http://` и `https://`. |
| **Базовое имя файла** | Латиница, без расширения. Имена частей будут вида `имя_001.mp4`, `имя_002.mp4`, … Если в каталоге уже есть файлы с таким префиксом, при старте выбирается **следующая свободная** трёхзначная часть. |
| **Режим хранения** | См. раздел [Режимы хранения](#3-режимы-хранения). |
| **Подпапка** | Заполняется **только** для режима **2b**: относительный путь внутри корня записи (например `nas/show1`). Недопустим выход «вверх» из корня (`..` и т.п.). |

Кнопка **«Начать запись»** сохраняет параметры в **историю** (дата и время, URL, имя, режим, подпапка) и запускает новую сессию.

**Лимит:** одновременно может быть не больше **двух независимых** активных записей (настраивается администратором через `MAX_INDEPENDENT_SESSIONS`). Автопродолжение **той же** сессии после обрыва **не** занимает второй слот.

### Сессии

Таблица показывает все сессии (с пагинацией, если их много).

| Колонка | Смысл |
|---------|--------|
| **Статус** | «Запись» — идёт запись; иначе — завершённое состояние (как в системе). |
| **Начало / окончание** | Время в **локальной** зоне сервера. |
| **Размер на диске** | Текущий растущий файл (пока идёт запись). |
| **Часть** | Номер текущей части цепочки. **Больше 1** у ещё активной строки обычно означает **автопродолжение** после сбоя сети/процесса для **того же** базового имени. |
| **PID** | Идентификатор процесса FFmpeg на сервере (для диагностики). |
| **Режим** | Число 1, 2 или 3 и подсказка **2a**, если включён сценарий скачивания в браузере. |
| **Имя** | Базовое имя записи. |
| **Текущий файл** | Относительный путь к текущему MP4. |
| **Части (скачать)** | Ссылки на **уже завершённые** части — скачивание через браузер. Для режима **2a** после завершения части имеет смысл **сохранить файл на ПК** через браузер (копия); файл на сервере при этом остаётся в каталоге записи. |
| **Действия** | **«Стоп»** — только для активной записи: **ручная** остановка **без** автопродолжения цепочки. |

Ссылка **JSON: статусы** ведёт на машиночитаемый ответ `GET /record/status` (обновление панели в браузере, интеграции).

### Файлы в каталоге записи

Список всех **`.mp4`** под корнем записи (рекурсивно), с датой изменения на диске.

- **download** — скачать файл.
- **ffprobe** — открыть текстовый вывод `ffprobe` в новой вкладке.
- **ffmpeg -v error** — проверка целостности; результат приходит сообщением на главной странице.
- **Удалить** — удаление с **подтверждением** в диалоге браузера. Удалённые файлы не восстанавливаются приложением.

### История записи

Кнопка **«История записи»** открывает окно со списком прошлых параметров запуска.

- **Повторить запись** — новая сессия с тем же URL, именем, режимом и подпапкой (как при ручном заполнении формы).
- **Удалить выбранную** — убирает строку из истории; **на уже записанные файлы не влияет**.

## 3. Режимы хранения

В форме значения **1**, **2**, **3** соответствуют терминам из ТЗ:

| В форме | В ТЗ | Смысл |
|---------|------|--------|
| **1** | Режим 1 | Запись в **корневой каталог** записи на сервере (или в томе Docker — см. README / DOCKER.md). |
| **2** | 2b | Запись в **подпапку** внутри этого корня. Поле **«Подпапка»** обязательно к осмысленному заполнению. Удобно для разнесения по папкам на NAS. |
| **3** | 2a | Как режим 1 по месту на сервере, плюс в интерфейсе напоминание **скачать копию на ПК** через браузер. Путь к папке на вашем компьютере **не передаётся** на сервер — только загрузка файла. |

---

## 4. Ручной стоп и автопродолжение

- **«Стоп»** — намеренная остановка: цепочка **не** продолжается сама, FFmpeg завершается мягко, MP4 обычно остаётся открываемым.
- **Обрыв потока / авария процесса** — при неисчерпанном лимите (по умолчанию до **5** продолжений, `MAX_CONTINUATIONS`) приложение может **автоматически** начать **следующую часть** (`…_002.mp4` и т.д.) **той же логической записи**. Это **не** новая независимая сессия и **не** расходует второй слот из двух.
- Если процесс убит **SIGKILL** (`kill -9`) или питание оборвано резко, последний файл может быть **обрезан** — это ограничение ОС, не «лечится» интерфейсом.

После **каждого** завершения части (и после стопа, и после естественного конца потока) в таблице появляются **ссылки на скачивание** завершённых частей.

## 5. Где лежат файлы

- **Локальный запуск** (без Docker): каталоги из `.env` — обычно `recordings/`, `data/state.sqlite3`, `logs/` относительно рабочей директории процесса. Подробнее — таблица переменных в [README.md](../README.md).
- **Docker**: на хосте рядом с `docker-compose.yml` папка **`docker-data/`** (`recordings`, `state.sqlite3`, `logs`). См. [DOCKER.md](../DOCKER.md).

---

## 6. Защита доступа (опционально)

Если администратор задал **`RECORDING_AUTH_TOKEN`** в конфигурации, все запросы к интерфейсу и API требуют заголовок:

`Authorization: Bearer <токен>`

В обычном браузере без расширений так не поработать — доступ рассчитан на сценарии с токеном или прокси. Если токен не задан, страница открывается без авторизации.

## 7. Типичные проблемы

| Симптом | Что проверить |
|---------|----------------|
| Не открывается страница | Правильный **хост и порт**; на macOS порт **5000** часто занят (AirPlay) — смените `FLASK_RUN_PORT` или `HOST_PORT` в Docker. |
| «0 KB» / пустой MP4 при живой записи | Возможна перегрузка канала **stderr** FFmpeg; по умолчанию хвост ошибок в API отключён. Администратор может включить `RECORDING_FFMPEG_STDERR_PIPE=1` для поля `ffmpeg_stderr_excerpt` в `/record/status` — на части систем это может ухудшить запись. |
| Не стартует вторая запись | Достигнут лимит **двух** независимых активных сессий — остановите одну или дождитесь завершения. |
| Ошибка подпапки (2b) | Путь должен быть **относительным**, без `..` и без выхода за корень записи. |

Логи приложения на сервере: файл **`app.log`** в каталоге логов (`logs/` локально или `docker-data/logs/` в Docker). Сообщения контейнера: `docker compose logs recorder` (см. DOCKER.md).
