# Техническое задание: запись HLS через веб‑интерфейс (Flask + FFmpeg)

**Статус:** согласовано заказчиком (2026‑05‑03).

---

## Часть A. Бизнес‑ТЗ (утверждено)

### A.1. Введение и цели

**Назначение:** дать оператору через браузер возможность запускать и останавливать запись HLS (`.m3u8`) в MP4 на стороне сервера (в перспективе — контейнер на Synology DS218+), контролировать статус, получать файлы и базовую диагностику, **минимизируя потерю контента** при нестабильном источнике за счёт переподключений и **авто‑продолжения в новый файл** в пределах лимита.

**Цели:**

- Управляемая запись без перекодирования в базовом сценарии (копирование потоков, корректная упаковка AAC в MP4 — см. приложение по FFmpeg).
- До **двух независимых** параллельных записей максимум.
- Выбор **режима/места сохранения:** по умолчанию запись на сервер (режим 1); дополнительно подпапка на NAS (2b) и доставка на ПК через браузер (2a).
- После **завершения каждой части** записи (**ручной стоп** и **естественное** окончание потока) — **ссылка(и) на скачивание** этой части.
- Устойчивость к перезапуску приложения: **восстановление состояния** активных записей по сохранённым данным и PID.

**Критерии успеха (качественно):** оператор понимает, что записывается и куда; может остановить запись без преднамеренного авто‑продолжения; при сбое получает цепочку файлов в рамках правил; может забрать файл по ссылке и/или через сценарий загрузки на свой компьютер; на NAS не более двух одновременных независимых записей.

### A.2. Глоссарий

| Термин | Определение |
|--------|-------------|
| Сессия записи | Одна логическая запись: URL, режим хранения, правила имён, цепочка частей при авариях. |
| Часть записи | Один выходной MP4; при авто‑продолжении следующая часть — новый файл. |
| Независимая запись | Отдельная сессия; учитывается в **лимите 2**. |
| Аварийное завершение | Завершение процесса записи **не** по команде «Стоп». |
| Режим хранения 1 | Запись в каталог на сервере/NAS (том контейнера); **по умолчанию** в UI. |
| Режим 2b | Запись в **подпапку** внутри разрешённого корня (относительный путь; защита от выхода за корень). |
| Режим 2a | После завершения части — **скачивание через браузер** на ПК; локальный путь задаёт ОС, не сервер. |

### A.3. Заинтересованные стороны и пользователи

- **Оператор** — единственная роль MVP.

### A.4. Область системы

**В скоупе**

- Ввод URL `http`/`https`, безопасные имена выходных файлов (`.mp4`).
- Запуск FFmpeg с параметрами устойчивости (переподключение), `-nostdin`, безопасный запуск процесса (список аргументов, не shell).
- Ручная остановка с приоритетом мягких сигналов (SIGINT → SIGTERM; SIGKILL только в крайнем случае).
- Лимит **2 независимые** активные сессии; авто‑продолжение **той же** сессии **не** занимает второй слот.
- При **аварии** — авто‑продолжение в следующую часть до исчерпания лимита попыток (**дефолт: 5**, настраивается).
- Именование частей: шаблон с порядковым суффиксом или временной меткой — фиксируется при проектировании; отображение в UI обязательно.
- **Режимы хранения в UI:** по умолчанию режим **1**; опционально **2b** и **2a** (оба допустимы). Рекомендация: файл на сервере сохраняется; **2a** инициирует загрузку копии у клиента (файл на сервере для списка/архива на NAS сохраняется).
- После **каждого завершения части** — ссылка на скачивание (**ручной стоп** и **естественное** завершение); для цепочки — отдельная ссылка на каждую завершённую часть.
- Список файлов, проверка целостности (`ffmpeg -v error …`), информация (`ffprobe`), удаление с подтверждением, логи.
- Персистентность состояния (JSON или SQLite) и **сверка PID** при старте приложения.
- Опциональная защита доступа из конфигурации.

**Вне скоупа MVP**

- Автосклейка цепочки MP4 внутри приложения (допускается справка для ручной склейки).
- Облако, CDN, multi‑tenant, юридическая экспертиза контента.

**Устаревшее относительно раннего черновика спеки**

- Кнопка «две параллельные записи одного URL» **не используется**; вместо этого — одна сессия с переподключением и авто‑продолжением в новую часть при аварии.

### A.5. User stories

1. Как оператор, я хочу ввести URL и параметры и **начать запись**.  
2. Как оператор, я хочу **остановить запись** явной командой без авто‑продолжения цепочки.  
3. Как оператор, я хочу видеть **статус** и **номер части**.  
4. Как оператор, при **аварии** я хочу **авто‑продолжение в новый файл** в пределе лимита.  
5. Как оператор, я хочу до **двух параллельных независимых записей**.  
6. Как оператор, после **перезапуска** приложения я хочу **актуальный статус** живых записей.  
7. Как оператор, я хочу **список файлов**, проверку, инфо, удаление.  
8. Как оператор, я хочу **опционально включить защиту доступа**.  
9. Как оператор, я хочу **выбрать режим сохранения** (1 по умолчанию, 2b и/или 2a).  
10. Как оператор, после **любого завершения части** я хочу **ссылку на скачивание** и при 2a — загрузку в браузере.

### A.6. Функциональные требования

| ID | Требование |
|----|------------|
| FR-001 | URL HLS только `http`/`https`. |
| FR-002 | Запись в MP4 с переподключением и `-c copy` в базовом сценарии; AAC → корректный MP4 (`-bsf:a aac_adtstoasc`). |
| FR-003 | Не более **2** активных **независимых** сессий; при превышении — отказ с сообщением. |
| FR-004 | **Ручная остановка:** без авто‑продолжения; мягкое завершение процесса. |
| FR-005 | **Авария:** при неисчерпанном лимите — следующая **часть**, новое имя по шаблону. |
| FR-006 | UI: режим хранения, путь (2b), текущая часть, история частей. |
| FR-007 | Режим хранения в UI; **по умолчанию режим 1**. |
| FR-008 | Режим 1: каталог сервера из конфигурации. |
| FR-009 | Режим 2b: относительная подпапка в whitelist корня; запрет path traversal. |
| FR-010 | Режим 2a: после завершения части — предложение/кнопка скачивания в браузере. |
| FR-011 | После завершения **каждой** части (ручной стоп или естественное окончание) — **ссылка на скачивание**; для цепочки — на каждую завершённую часть. |
| FR-012 | Список файлов, целостность, ffprobe, удаление (+ логи по правилам проекта), скачивание с защитой от обхода каталога. |
| FR-013 | Персистентность и восстановление при старте с проверкой PID. |
| FR-014 | Опциональная аутентификация при включении в конфигурации. |

### A.7. Нефункциональные требования

| ID | Требование |
|----|------------|
| NFR-001 | Внешние команды только через список аргументов, без произвольного shell. |
| NFR-002 | Валидация имён и путей; whitelist корней; только `.mp4`; защита от path traversal. |
| NFR-003 | Устойчивость к кратковременным обрывам (параметры FFmpeg). |
| NFR-004 | Состояние на диске (JSON или SQLite), том для Docker сохраняется между перезапусками. |
| NFR-005 | Окружения: локально (MVP), Docker на Synology DS218+; тома для `recordings`/состояния, разумные лимиты ресурсов. |
| NFR-006 | Логирование: старт/стоп/авария/авто‑продолжение/ошибки валидации. |
| NFR-007 | Ссылки на скачивание не обходят опциональную авторизацию. |
| NFR-008 | Справка в UI: различие 2b (папка на NAS) и 2a (файл на ПК через браузер). |

### A.8. Бизнес‑правила

- Авто‑продолжение только после **аварии**, не после ручного стопа.  
- Лимит **2** — только на **независимые** сессии.  
- По умолчанию в форме новой записи — **режим 1**.  
- Ссылка на скачивание после завершения части — **всегда** (ручной стоп и естественное завершение).  
- Ответственность за правомерность записи контента — на операторе.

### A.9. Риски и ограничения

- Браузер не передаёт серверу произвольный локальный путь ПК; 2a — только загрузка.  
- MP4 после аварии может быть неполным; следующая часть — новый файл.  
- DS218+: RAM, диск, сеть при двух потоках.  
- Ожидания «путь на ноутбуке» в поле для сервера — снижать через UX и справку.

## Часть B. Техническая справка (ориентир для реализации)

Ниже — материалы из исходного черновика спецификации; команды и структура могут уточняться под утверждённое ТЗ (цепочки частей, режимы 1/2a/2b, персистентность).

### B.1. Пример ссылки потока (иллюстрация)

Фиктивный URL для документации; для тестов используйте свой легальный источник HLS.

```text
https://cdn.example.org/live/channel-id/index.m3u8
```

### B.2. Базовая команда FFmpeg

```bash
ffmpeg -nostdin \
-i "URL" \
-c copy -bsf:a aac_adtstoasc recordings/output1.mp4
```

| Параметр | Назначение |
|----------|------------|
| `-nostdin` | Не зависать при фоновом запуске |
| `-c copy` | Без перекодирования |
| `-bsf:a aac_adtstoasc` | AAC пригодный для MP4 |

Флаги `-reconnect*` в продукте **не используются**: на ряде HLS они провоцировали бесконечные реконнекты и нулевой размер файла; устойчивость к обрывам — через авто‑продолжение в новый файл в приложении.

### B.3. Проверка целостности

```bash
ffmpeg -v error -i recordings/output1.mp4 -f null -
```

### B.4. Длительность и информация

```bash
ffprobe -v error -show_entries format=duration -of default=noprint_wrappers=1:nokey=1 recordings/output1.mp4
ffprobe -v error -show_format -show_streams recordings/output1.mp4
```
